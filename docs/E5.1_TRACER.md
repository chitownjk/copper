# E5.1 tracer bullet — breakdown

E5.1 is sized XL and the difficulty is structural: silent failures, entitlement/
provisioning coupling, and approval UX. This breaks the tracer bullet into
five independently verifiable steps. Scope is deliberately smaller than the
full E5.1 story: **a test pattern selectable in Photo Booth and Zoom. No sink
stream, no effects, no compositor, no onboarding UI.** (The sink-stream
handshake is its own step after the tracer proves the install path.)

| Step | Deliverable | Verified by |
|---|---|---|
| **a. Target plumbing** | `CameraExtension` system-extension target embedded at `Contents/Library/SystemExtensions/` | Bundle layout on disk; `codesign -dv` on both bundles |
| **b. Provisioning** | App carries `com.apple.developer.system-extension.install`; extension is sandboxed; both signed by team GJPMXXQTWN | `codesign -d --entitlements -` shows the grants; app still launches (AMFI kills apps with unauthorized restricted entitlements — a passing build is not proof) |
| **c. Extension code** | `CMIOExtensionProvider`/`Device`/`Stream` serving a 1080p30 generated test pattern with a live frame counter | Extension binary links and starts standalone (`CMIOExtension` plist keys validated) |
| **d. Activation path** | `OSSystemExtensionRequest` wrapper + `--install-camera-extension` / `--uninstall-camera-extension` launch flags + Settings button | Request reaches `needsUserApproval` / `completed` delegate callbacks, logged |
| **e. End-to-end on this Mac** | Approved extension appears as a camera | `systemextensionsctl list`; AVCaptureDevice discovery probe; Photo Booth/Zoom by hand |

## Known failure modes (pre-empted, from OBS #7777 / Apple sample / forums)

1. **App not in `/Applications`** → activation fails with
   `OSSystemExtensionError.unsupportedParentBundleLocation` (code 3). Dev loop
   is: build → copy to /Applications → launch from there. `systemextensionsctl
   developer on` would lift this but needs root (user action, optional).
2. **`CMIOExtensionMachServiceName` prefix mismatch** → extension activates but
   *never appears in any picker*, silently. The name must be prefixed by the
   team ID (`GJPMXXQTWN.`) or an app group the extension is a member of. We use
   `$(TeamIdentifierPrefix)$(PRODUCT_BUNDLE_IDENTIFIER)`.
3. **Restricted entitlement without a provisioning profile** → the *app* is
   killed at launch by AMFI. `com.apple.developer.system-extension.install`
   requires an embedded macOS provisioning profile; automatic signing mints one
   only if Xcode is signed into the team.
4. **Extension not sandboxed** → activation rejected at validation time.
5. **Replacing an existing version** silently queues "will complete after
   reboot" — check `systemextensionsctl list` for `[activated waiting for user]`
   vs `[activated enabled]` states rather than trusting the delegate alone.
6. **Approval moved** in macOS 15+: System Settings → General → Login Items &
   Extensions → Camera Extensions.

## Hard-rule guardrail

Rule 2 (no effects/heavy logic in the extension) holds: the extension renders
only its built-in placeholder/test card. When the sink stream lands in a later
step, the extension still only *relays* frames pushed by the app.
